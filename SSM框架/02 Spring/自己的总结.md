Spring是IOC(控制反转)与AOP(面向切面编程)的，感觉这个主要是降低耦合性
将对象交给bean仓库管理
开始讲的是降低耦合性(耦合是指的是程序之间的依赖关系)就像牵一发动全身的感觉
主要小项目没啥区别 但大项目就影响大了 
降低耦合性是思路 可以通过封装工具类，创建工厂，配置文件 避免new 用反射的机制等的方法来降低 我感觉啊

先讲的工厂解耦
哦我看懂了 就是开始Dao层创建的要在service层使用时通常要用new关键字 这样提高了耦合性
```java
public class AccountServiceImpl implements AccountService{
	@Override  
	public void addAccount() {
	AccountDao accountDao=new AccountDaoImpl();//这样增加耦合性
	}
}
```
现在通过创建工厂加配置文件来降低
先创建配置文件 文件里面放方法的全限定名称 在通过工厂对象的方法来获取new的全限定名称
```java
AccountDao accountDao= (AccountDao) BeanFactory.getBean("mybatisAccountDao");
这样的通过工厂来进行
mybatisAccountDao=com.q.dao.impl.MybatisAccountDaoImpl
```
但每次创建的对象的地址都不一样 当只调用对象不作修改时 重复创建浪费资源 所有可以改成单例来节省资源 那怎么创建单例呢 在工厂中可以创建Map对象来存储 这样对象就是一个了

上面就是对ioc的大体解释
开始都是我们对象自己创建 想new就new 但耦合性强
下面的是工厂代理创建对象 不是想new就new 要通过工厂才行 但这样通过工厂加配置文件的形式太过繁琐了

spring给我们优化了

在sprint环境管理bean  
bean标签就是帮助我们管理bean的标签将bean放在sprint的ioc容器里面  
id就是bean的名称 值任意 但必须唯一  
class：bean所属类的全限定名称

ApplicationContext是spring给我们提供的核心容器
ApplicationContext继承与BeanFactory BeanFactory才是顶级容器
那两个区别是什么？
ApplicationContext才用的是立即加载的形式  当ApplicationContext 对象创建时bean管理的对象的创建了
对象要交给bean管理
这个BeanFactory是BeanFactory对象创建时没有创建bean管理的对象，当要第一次获取bean管理的对象时才创建

spring中对bean的管理方法是在基于spring的xml中配置bean对象
还可以通过bean管理工厂来实例化对象
```java
<!--    factory-bean：引用工厂bean的id-->  
<!--    factory-method：引用的是工厂bean中的获取bean的方法名称-->

<bean id="personFactory" class="com.xq.factory.PersonFactory"></bean>
<bean id="personDao" class="com.xq.dao.impl.PersonDaoImpl" factory-bean="personFactory" factory-method="getPerson">
1. 先创建 `PersonFactory` 实例
2. 调用 `personFactory.getPerson()` 方法
3. 把 `getPerson()` 的返回值作为 `personDao` 这个 Bean
```
下面是工厂的静态方法实现实例化对象

```java
public class OrderFactory {
   public static OrderDao getOrder(){
       return new OrderDaoImpl();
  }
  
  <bean id="orderFactory" class="com.xq.factory.OrderFactory" factory-
  method="getOrder">
```
这样就可以直接使用工厂的方法来实例化
```java
OrderDao orderDao=(OrderDao) context.getBean("orderFactory")
直接调用工厂里面的getOrder方法了
```

bean的作用域
默认bean是单例的 可以通过scope属性修改
singleton：单例的（默认值）
prototype：多例的
request：作用于web应用的请求范围
session：作用于web应用的会话范围
global-session：作用于集群环境的会话范围（全局会话范围），当不是集群环境时，它就是
session。

bean的生命周期
单例的与容器的生命周期一样 容器创建时bean对象就创建了 容器销毁时bean对象也销毁了
那么多例呢 
创建时 是在创建对象的时候创建 只有对象一直使用就一直存活 长时间不用 且没有别的对象引用时 将于java的垃圾回收器回收

DI
的作用是 依赖关系的管理，依赖都交给spring来维护
在当前类需要用到其他类的对象，由spring为我们提供，我们只需要在配置文件中说明
依赖关系的维护：就称之为依赖注入
依赖注入：
能注入的数据：有三类
基本类型和String
其他bean类型（在配置文件中或者注解配置过的bean）
复杂类型/集合类型

注入的方式：有三种
第一种：使用构造函数提供
第二种：使用set方法提供
第三种：使用注解提供

构造函数注入
在bean里面
name（最常用）：用于指定给构造函数中指定名称的参数赋值
value：用于提供基本类型和String类型的数据
ref：用于指定其他的bean类型数据（它指的就是在spring的ioc核心容器中出现过的bean对象）
优势：
在获取bean对象时，注入数据是必须的操作，否则对象无法创建成功（因为没有默认空参构造）
弊端：
改变了bean对象的实例化方式，使我们在创建对象时，如果用不到这些数据，也必须提供

set方法注入(默认的)
涉及的标签：property
出现的位置：bean标签的内部
标签的属性：
name：用于指定注入时所调用的set方法名称（如：setName --> name）
value：用于提供基本类型和String类型的数据
ref：用于指定其他的bean类型数据。它指的就是在spring的ioc核心容器中出现过的bean对象

复杂类型数据注入

```java
<bean id="animal" class="com.lq.pojo.Animal">  
    <!--注入数组类型的值-->  
    <property name="strs">  
	    <array>    
		    <value>str1</value>  
		    <value>str2</value>  
		    <value>str3</value>  
	    </array>    
    </property>    
    
    
    <!--注入list-->  
    <property name="list">  
	    <list>    
		    <value>list1</value>  
		    <value>list2</value>  
		    <value>list3</value>  
	    </list>    
    </property>    
    <!--注入set-->  
    <property name="set">  
	   <set>    
		   <value>s1</value>  
		   <value>s2</value>  
		   <value>s3</value>  
	    </set>    
    </property>    
    
    <!--注入Map-->  
    <property name="map">  
	    <map>    
		    <entry key="k1" value="v1"></entry>  
		    <entry key="k2" value="v2"></entry>  
		    <entry key="k3" value="v3"></entry>  
	    </map>    
    </property>    
    <!--注入properties-->  
    <property name="pros">  
	    <props> 
		    <prop key="p1">v1</prop>  
		    <prop key="p2">v2</prop>  
		    <prop key="p3">v3</prop>  
	    </props>    
    </property>
</bean>

```
